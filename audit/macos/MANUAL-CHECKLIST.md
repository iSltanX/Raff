# قائمة الفحص اليدوي على macOS — رفّ

> بيانات **صناعية فقط**. لا تنسخ أسرارًا حقيقية ولا ملفات شخصية. استعمل نسخة **debug** بمجلد بيانات معزول. لا تستعمل نقطة البلاغات الحقيقية ولا تثبّت تحديثًا.

## حالة التنفيذ

**لم يُنفَّذ أي سيناريو من هذه القائمة على جهاز حقيقي حتى 2026-10-13**: النتيجة الفعلية فارغة في الإحدى والثلاثين كلها.

**نجاح CI لا يغني عنها.** `npm test` يشغّل الواجهة في jsdom مع خلفية وهمية، و`cargo test` يشغّل المخزن دون `AppHandle`. لا شيء منهما يلمس:
- WKWebView الحقيقي داخل Tauri، ولا الشفافية والزجاج فوق سطح المكتب؛
- `NSPasteboard`، ولا اللصق بـ⌘V، ولا إذن تسهيلات الاستخدام؛
- شريط القوائم، ولا سكون النظام، ولا LaunchAgent؛
- انقطاع الكهرباء.

**الأولوية بعد دمج #4 و#5**، أي ما تغيّر سلوكه ولم يُرَ في التطبيق الحقيقي:

| السيناريو | ما يثبته |
|---|---|
| 10 | H10: الإيقاف المؤقت عبر سكون حقيقي |
| 26 | RAFF-AUD-002 وRAFF-AUD-003: تنبيه الإعدادات غير المقروءة ونسخ الاسترداد |
| 27 | RAFF-AUD-001: إلغاء التثبيت عند الحد |
| 28 | H6: تغيير شريط القوائم لا تلغيه نافذة الإعدادات |
| 29 | H7: لصقتان سريعتان |
| 30 | تباين الوضع الداكن فوق سطح مكتب فاتح |
| 31 | تتبّع الإقلاع لنسخة debug وحدها |

ثم البقية كما هي.

## الإعداد

`tauri.conf.json` لا يعرّف `devUrl` ولا `beforeDevCommand`، فوضع التطوير يقدّم `frontendDist: ../dist` كما هو. ابنِ الواجهة أولًا:

```bash
npm ci
npm run build:frontend
export RAFF_DEV_ISOLATED=1                 # debug فقط: يعمل بجانب رفّ المثبّت بدل تسليم الإطلاق له
export RAFF_DATA_DIR="$(mktemp -d)"        # debug فقط: لا يقرأ ولا يكتب سجل رفّ المثبّت
export RAFF_REPORT_ENDPOINT=http://127.0.0.1:9/v1/reports   # debug فقط: مسار فشل البلاغ
echo "$RAFF_DATA_DIR"
npm run tauri dev
```

> **تعارض الاختصار العام:** الاختصار الافتراضي `shift+super+v` (⇧⌘V). إن كان رفّ المثبّت يعمل، فسيفشل تسجيل الاختصار في نسخة التطوير. الحل: أغلق رفّ المثبّت من شريط القوائم قبل البدء، أو غيّر اختصار نسخة التطوير من إعداداتها. المجلد معزول، فلا يتأثر المثبّت.
>
> المتغيرات الثلاثة تُتجاهل في نسخ release (`cfg!(debug_assertions)`). تحقق من `echo $RAFF_DATA_DIR` قبل أي خطوة تكتب ملفات.
>
> علامة التتبع `/tmp/raff-trace-on` تفعّل التتبع في نسخ debug وحدها (أُصلح RAFF-AUD-006). يُكتب السجل في `$RAFF_DATA_DIR/startup-trace.log` بصلاحيات 0600، ولا شيء في `/tmp`.

الفحوص الآلية: `bash audit/macos/run-native-checks.sh` (اختياريًا `--mutants`).

### 26. إفساد ملف JSON عمدًا (في المجلد المؤقت فقط)

- **الشروط المسبقة:** أغلق رفّ. **تأكد أن المسار تحت `$RAFF_DATA_DIR`.**

### 27. إلغاء تثبيت عنصر قديم والسجل ممتلئ (RAFF-AUD-001)

- **الشروط المسبقة:** سعة السجل 200 في الإعدادات.
- **الخطوات:**

  1. انسخ نصًا مميّزًا «قديم-1» وثبّته.
  2. انسخ 200 نص جديد على الأقل، مثلًا: `for i in $(seq 1 210); do printf "n$i" | pbcopy; sleep 0.6; done`.

## ما لا تغطيه هذه القائمة ولا CI

- **H3، انقطاع الكهرباء أثناء الكتابة:** لا يُحاكى يدويًا بأمان. الضمان في #5 أن الإعدادات واليوميتين تمرّ بـ`F_FULLFSYNC`، وسجل الحافظة لا يمرّ عن قصد.
- **`Retry-After: 0` من خادم البلاغات الحقيقي:** لا يُستفز يدويًا. محميّ باختبار خادم محلي واختبار نافذة.
- **إعلانات ثغرات جديدة بعد الدمج:** `cargo audit` في CI يلتقطها عند أول تشغيل بعدها.
